# 功能三 · 队伍联动（PokeDex Bridge）

## 目标

在 PokéRogue 游戏页里，读出**我方队伍**和**对手**，对照本地图鉴展示它们的属性、稀有度、出现区域与推荐配招。要求手动开关、启动时检测目标网站/游戏是否就绪。

## 形态选择

| 候选 | 结论 |
|---|---|
| Tampermonkey 用户脚本 | ✅ 采用：零安装成本、天然只在目标站点运行 |
| Chrome 扩展 | 能力更强但需加载未打包扩展 |
| 桌面伴侣 + CDP | 能主动检测浏览器标签，但要以调试端口启动浏览器，过重 |

## 数据接口调研（2026-10-22）

| 目标 | 结论 |
|---|---|
| `window.game` | ❌ 不存在：`src/main.ts` 里是 `const game = new Phaser.Game(...)`，未挂到 window |
| `window.gameInfo` | ✅ 存在，官方**有意暴露**且带版本（`gameInfoVersion: "2.1.0"`），字段见下 |
| 对手数据 | ❌ `gameInfo` 只含 `this.party`（我方），没有对手 |
| 存档加密 | 密钥 `saveKey` 是源码中的**硬编码常量**（`src/constants.ts`，注释自述 "Temporary"） |
| 存档内容 | `sessionData*` 里同时有 `party` 与 `enemyParty` 快照 |

### `window.gameInfo` 字段（节选）

`playTime`、`gameMode`、`biome`、`wave`、`luck`、`party[]`；队伍成员含：
`name`、`nickname`、`gender`、`form`、`types`、`tempTypes`、`teraType`、`level`、`currentHP`、`maxHP`、
`status`、`moveset`、`tempMoveset`、`ability`、`tempAbility`、`passiveAbility`、`isPassiveEnabled`、
`nature`、`baseStats`、`tempStats`、`statStages`、`shiny`、`variant`、`isFusion`。

## 实现方案

### 1. 我方队伍
直接读 `window.gameInfo.party`——官方接口，稳定。

### 2. 对手：为什么不是「实时」

最初设想用 `Error.prepareStackTrace` + `CallSite.getThis()` 在 `updateGameInfo()` 赋值 `window.gameInfo`
时捕获 `BattleScene` 实例。**实测结论：走不通。**

- 用 Node（同为 V8）复现：setter 所在的调用帧 `getThis()` 返回 `undefined`；
  原因是 ES class 方法运行在严格模式，V8 对严格模式帧不暴露 `this`。
- 因此脚本改为**低成本探测** `window.game`、`window.Phaser.GAMES`、`window.scene`
  （正常发行版不存在，仅调试/特殊环境可能命中），失败就走存档快照。

### 3. 对手（存档快照）

1. 读取 `localStorage` 中所有 `sessionData*` 键；
2. 用 `CryptoJS.AES.decrypt(raw, saveKey)` 解密；
3. 取 `enemyParty`（`PokemonData[]`）；
4. 关键字段（见 `src/system/pokemon-data.ts`）：
   `species`（**物种 ID，不是实例 ID**）、`level`、`hp`、`stats[]`、`nature`、`abilityIndex`、`passive`、`boss`、`bossSegments`、`shiny`、`moveset[]`；
5. 用 `species`（基础物种 = 全国图鉴号）回查本地索引，补名称/属性/稀有度/区域；`abilityIndex` 用于在特性列表中定位特性。

> 踩坑记录：`PokemonData.id` 是**实例 ID**（如 `148554607`），早期版本误当物种 ID 用，导致对手显示成 `#148554607`。

局限：快照在换波/存档时更新，可能滞后一回合；招式（moveId）缺少名称映射，暂不展示。

### 4. 名称匹配（中英文）

| 情形 | 匹配方式 |
|---|---|
| 中文界面 | 与 `pokemon.data.js` 的 `name` 精确匹配 |
| 英文界面 | `normalizeKey` 归一化后与图鉴 slug 匹配：`Mr. Mime → mr-mime`、`Nidoran♀ → nidoran-f`、`Farfetch'd → farfetchd`、`Ho-Oh → ho-oh` |
| 兜底 | 图鉴号（我方场景数据可得 `species.speciesId`） |

匹配失败时显示「图鉴未收录」，但仍展示游戏内原始数据（属性、等级、HP、招式）。

### 5. 属性 / 性格译名

- 属性：`PokemonType` 枚举（0 一般 … 17 妖精，18 星晶）→ 中文；
  `gameInfo.types` 给的是英文枚举名（`Fire`）→ 中文映射。
- 性格：`Nature` 枚举 0~24 → 中文（`15 → 内敛`）。

## 交互与检测

- **手动开关**：右下角悬浮按钮；状态存 `localStorage['pokedex-bridge-enabled']`，刷新后保持。
- **启动检测**：面板顶部三行状态——网站 ✓、游戏是否加载（`gameInfo`/场景是否存在）、存档是否可读。
- **数据刷新**：开启时每 1.5 秒扫描一次；`gameInfo` 赋值时也会触发一次。

## 已知限制

1. 实时对手依赖 V8 的 `CallSite.getThis()` 行为，浏览器/游戏更新后可能失效 → 自动降级。
2. 存档降级路径拿不到招式/特性（存档只存 id 与数值）。
3. 只收录 372 只稀有+ 宝可梦；普通/罕见宝可梦显示「图鉴未收录」。
4. 未做写入/自动化操作，纯只读。
5. **未在真实浏览器中验证**（开发环境没有浏览器自动化），首次使用需按 `userscript/README.md` 的排查表确认。
