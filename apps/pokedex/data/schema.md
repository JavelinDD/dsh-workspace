# 数据契约（schema）

本文件是录入数据、模板解析、界面渲染三方的唯一约定。任何字段变更必须先改这里。

## 1. 顶层结构

```js
window.POKEDEX_SEED = {
  meta: {
    version: "2.0.0",
    schemaVersion: 1,
    updatedAt: "2026-10-22",
    source: "pokeroguegame.net（数据源自开源游戏 PokéRogue 官方数据）",
    generatedBy: "apps/pokedex/tools/build-dataset.mjs",
    note: "去重口径与字段说明"
  },
  pokemons: [ /* 宝可梦记录数组，见下 */ ]
};
```

### 1.1 数据来源与筛选口径（2026-10-22 起）

当前 `pokemon.data.js` 由抓取脚本生成，规则如下：

1. 数据源：`pokeroguegame.net` 的中文图鉴（站点自述数据来自开源游戏 PokéRogue）。
2. **只收录「最低稀有度 ≥ 稀有」的物种**：某只若在任意区域是普通/罕见，整只不收录。
3. **Boss 去重**：同一只同时有 Boss 与非 Boss 条目时，丢弃 Boss 条目；纯 Boss 物种不收录。
4. **区域稀有度保留站点真实值**（如森林=稀有、神殿=超级稀有）；
   列表徽章与排序使用 `minRarity`，即所有区域中的最低档。
5. 推荐招式为自动筛选：本系优先 → 威力降序，取前 10；不足时用变化招式补齐。
6. 站点**不提供性格数据**，抓取记录 `natures` 为空；性格只能手工录入。
7. 区域命名以本仓库 `config.js` 为准（站点「发电厂」→ 本项目「发电站」）。

## 2. 宝可梦记录

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识，英文小写或拼音，由名称生成，冲突时加序号 |
| `name` | string | ✅ | 中文名，如「胡帕」 |
| `aliases` | string[] | | 别名/英文名/称号，参与搜索，如 `["Hoopa","幻之宝可梦"]` |
| `formName` | string | | 形态名，默认「普通形态」；特殊形态单开一条记录并用 `aliases` 区分 |
| `types` | string[] | | 属性，1~2 个，取值见属性表 |
| `dexNo` | number | | 图鉴编号（可空） |
| `abilities` | Ability[] | | 特性 |
| `passives` | Passive[] | | 被动 |
| `natures` | Nature[] | | 推荐性格 |
| `moves` | Move[] | | 推荐配招，**最多 10 条** |
| `regions` | RegionEntry[] | | 出现区域与稀有度，可多条 |
| `evolution` | Evolution | | 进化关系 |
| `notes` | string | | 备注 |
| `source` | string | | 数据来源 |
| `updatedAt` | string | | ISO 日期 |

### 2.1 Ability（特性）

```js
{ "name": "魔术师", "desc": "使用招式时，可以将对手的道具夺取并替换", "hidden": false }
```

### 2.2 Passive（被动）

```js
{ "name": "跟风", "desc": "每次自身被攻击后，攻击方有概率陷入异常状态" }
```

### 2.3 Nature（推荐性格）

```js
{ "name": "内敛", "delta": "+特攻 -攻击", "reason": "特攻输出首选" }
```

- `delta` 统一写成 `+能力 -能力` 的形式（中间空格，便于解析与展示）。

### 2.4 Move（推荐招式）

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 招式名，如「异次元洞」 |
| `type` | string | 属性，如「超能力」 |
| `category` | string | `物理` / `特殊` / `变化` |
| `power` | number \| null | 威力；变化招式为 null |
| `accuracy` | number \| "必中" \| null | 命中率百分比或「必中」 |
| `priority` | number | 优先度，默认 0 |
| `effect` | string | 招式效果描述（原文） |
| `chance` | number \| null | 特殊效果触发概率（%） |
| `note` | string | 补充说明（可选） |

```js
{
  "name": "暗影球",
  "type": "幽灵",
  "category": "特殊",
  "power": 80,
  "accuracy": 100,
  "priority": 0,
  "effect": "有20%概率降低目标特防1级",
  "chance": 20
}
```

### 2.5 RegionEntry（区域与稀有度）

```js
{ "region": "神殿", "rarity": "超级稀有", "note": "Boss" }
```

- `region` 必须取自 `data/config.js` 的 `REGIONS`；不在列表中的会给出警告，但允许保存（便于后续扩展）。
- `rarity` 必须取自 `RARITIES`，或在 `RARITY_ALIASES` 中有映射（如「非常稀有」→「超级稀有」）。

### 2.6 Evolution（进化关系）

```js
{
  "prev": [{ "name": "力壮鸡", "method": "等级16" }],
  "next": [{ "name": "火焰鸡", "method": "等级36" }],
  "typeChange": "火/格斗 → 火/格斗"
}
```

## 3. 枚举

### 3.1 稀有度（5 档，从低到高）

`普通` → `罕见` → `稀有` → `超级稀有` → `极其稀有`

别名映射（自动归一，不算错）：

| 写法 | 归一为 |
|---|---|
| 非常稀有 / Super Rare / SR | 超级稀有 |
| 极稀有 / 极其稀有 / Ultra Rare | 极其稀有 |
| 常见 | 普通 |
| 少见 | 罕见 |
| Boss | 不占档位，写入 `note: "Boss"` |

### 3.2 区域（34 类）

城镇、平原、草地、高草丛、城市、森林、海洋、沼泽、沙滩、湖泊、海底、山脉、不毛之地、洞窟、沙漠、寒冰洞窟、花丛、发电站、火山、墓地、道场、工厂、遗迹、荒地龙巢、幽谷深渊、太空、工地、丛林、妖精洞窟、神殿、陋巷、冰雪森林、岛屿、研究所

> 说明：「荒地龙巢」按单一区域收录。若实际应为「荒地」「龙巢」两类，只需修改 `data/config.js` 的 `REGIONS` 数组，无需改代码。

### 3.3 属性

一般、火、水、草、电、冰、格斗、毒、地面、飞行、超能力、虫、岩石、幽灵、龙、恶、钢、妖精

## 4. 模板文本格式

用「+」开头，后接标签段，标签段以中文冒号分隔：

```
<名称> + <特性> + <被动> + <性格> + 推荐招式
特性：… 被动：… 出现区域：…（可多个，用 / 或 、 分隔）
稀有度：…（可带 / Boss）
性格推荐：…（+能力，-能力）
推荐招式：
<招式名>：<属性>属性<物理|特殊|变化>招式，威力<N>，命中<N>%，<效果描述>。
```

解析规则：

1. 名称取开头「+」前的第一段；其后三段分别视作特性、被动、性格的**兜底值**（若下方标签段缺失则采用）。
2. 标签段依次为：`特性：`、`被动：`、`出现区域：`、`稀有度：`、`性格推荐：`、`推荐招式：`。
3. 招式以「招式名：」开头，以「。」或换行分隔；单条内提取属性、分类、威力、命中、优先度、概率。
4. 无法识别的内容写入 `warnings`，返回给用户确认，不静默丢弃。

## 5. 校验规则（保存与导入时执行）

- `name` 非空且长度 ≤ 20
- `moves.length` ≤ 10
- `regions[].rarity` 命中枚举或别名
- `types` 中每个值命中属性表
- `id` 唯一；同名记录给出重复告警
- `natures[].delta` 符合 `^[+-]能力( [+-]能力)?$`
